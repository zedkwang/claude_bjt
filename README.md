# BJT 読みドリル

JLPT N1 보유자가 **한자 표기를 보고 이미 알고 있는 일본어 발음을 바로 떠올리도록** 훈련하는 무한 반복 읽기 드릴입니다.
BJT 고득점과 비즈니스 일본어 한자 읽기 자동화를 목표로 합니다.

## 실행

```bash
cd claude_bjt
npm install      # 처음 한 번
npm run dev      # http://localhost:5173 접속
```

그 밖의 명령:

| 명령 | 용도 |
| --- | --- |
| `npm test` | 정답 판정·복습 알고리즘·출제 순서 단위 테스트 |
| `npm run validate` | 콘텐츠 JSON 검증 (형식, 히라가나 여부, 중복) |
| `npm run build` | 배포용 정적 파일 생성 (`dist/`) |

## 학습 방식: 무한 모드

앱을 열면 바로 문제가 나오고, 원하는 만큼 풀다가 언제든 닫으면 됩니다. 답할 때마다 자동 저장됩니다.

다음 문제는 아래 순서로 고릅니다.

1. **재학습**: 방금 틀린 문항이 4문제 이상 지난 뒤 다시 나옵니다.
2. **복습 ↔ 신규**: 복습 시점이 된 문항과 신규 문항을 섞어 냅니다. 신규 비율은 기본 30%이며 설정에서 바꿀 수 있습니다.
3. **반복**: 복습할 문항도 신규 문항도 없으면, 오답률이 높거나 망설였거나 반응이 느린 문항을 가중치를 주어 계속 냅니다. 그래서 문제가 끊기지 않습니다.

신규 문항의 순서는 다음과 같습니다.

- Priority 1(비즈니스 핵심) → 2(훈독 업무 표현) → 3(N1 한자어) 순서를 기본으로, 세 그룹을 번갈아 섞어서 냅니다.
- **단어 → 복합어 → 문장** 순서로 진행합니다. 복합어와 문장은 그 안에 든 한자의 70% 이상을 먼저 본 뒤에 나옵니다. 레벨 필터로 직접 고르면 이 제한이 없어집니다.

### 복습 간격

| 결과 | 다음 복습 |
| --- | --- |
| 오답 | 같은 세션 안에서 재학습 → 맞히면 다음 날 |
| 정답 | 1일 → 3일 → 7일 → 14일 → 30일 → 60일 → 120일 |
| 정답이지만 망설임 | 간격을 늘리지 않고 같은 간격으로 다시 확인 |

**망설임**은 입력을 시작하기까지 기준 시간(기본 3초)보다 오래 걸린 경우입니다. 문장 문항에는 적용하지 않습니다.
맞혔더라도 "생각해서 맞힌 것"은 아직 자동화되지 않았다고 보고 다시 냅니다.

### 정답 판정

- 입력은 히라가나 기준이며, 가타카나로 입력해도 인정합니다. 로마자 입력(`shounin`)도 됩니다.
- 공백과 문장부호는 무시합니다.
- 문장 문항에서는 조사 は/へ/を를 わ/え/お로 입력해도 인정합니다.
- 사소한 오류는 **△ 거의 맞음**으로 따로 표시합니다. 해당하는 오류는 장음(しょにん), 촉음(けさん), 탁음·연탁(てつつき), 요음(しようにん)입니다. 복습 기록에는 오답으로 남습니다.
- IME 입력 실수라면 **오타로 처리 (T)** 를 눌러 정답으로 되돌릴 수 있습니다.
- 한자로 변환된 채 제출하면 판정하지 않고 다시 입력하도록 안내합니다.

### 단축키 (답한 뒤)

| 키 | 동작 |
| --- | --- |
| `Enter` | 다음 문제 |
| `M` | 뜻 보기/숨기기 |
| `T` | 오타로 처리 |
| 빈 칸에서 `Enter` | 모름 |

한국어 뜻은 기본으로 숨겨 둡니다. `漢字 → 한국어 → 日本語` 경로가 강화되지 않게 하기 위해서입니다. 뜻은 답한 뒤에만 볼 수 있습니다.

## 화면

- **학습**: 필터(전체 / 훈독·혼합 / 오답만 / 망설임, 레벨, 카테고리), 대기 현황, 이번 세션 기록
- **통계**: 평균 반응 시간, Reading Accuracy, 첫 시도 정답률, 반복 오답률, 7일·30일 리텐션, 진도, 일별 추이, 망설임 TOP 20, 오답 TOP 20, 오답 유형
- **단어장**: 전체 문항 검색, 문항별 정답률·복습 간격·다음 복습일
- **설정**: 망설임 기준, 신규 비율, 로마자 입력, 백업 내려받기/불러오기, 초기화

## 데이터 저장

학습 기록은 **이 브라우저의 localStorage**에만 저장됩니다. 서버는 없습니다.
브라우저 데이터를 지우거나 다른 브라우저·PC에서 열면 기록이 보이지 않습니다. **설정 → 백업 내려받기**로 가끔 JSON 파일을 받아 두세요.

## 콘텐츠

`src/data/*.json` 파일을 모두 읽어서 합칩니다.

| 파일 | 내용 | 레벨 |
| --- | --- | --- |
| `p1_business_core.json` | 비즈니스 고빈도 한자어 (Priority 1) | 단어 |
| `p2_kunyomi.json` | 훈독·혼합 읽기 업무 표현 (Priority 2) | 단어 |
| `p3_n1_vocab.json` | JLPT N1 고빈도 한자어, 헷갈리는 읽기 (Priority 3) | 단어 |
| `compounds.json` | 비즈니스 복합어 | 복합어 |
| `sentences.json` | 짧은 문장 50 + 비즈니스 문장 50 (일부는 N1 문법 포함) | 문장 |

> 읽기 데이터는 AI가 작성했습니다. 틀린 읽기를 발견하면 해당 JSON의 `reading`을 고치거나, 대체 읽기를 `alt_readings`에 추가해 주세요.

### 문항 추가하기

위 파일에 항목을 추가하거나 `src/data/` 안에 새 `.json` 파일(배열)을 만들면 자동으로 반영됩니다. 추가한 뒤에는 `npm run validate`로 검증하세요.

```json
{
  "id": "my-001",
  "expression": "見積書",
  "reading": "みつもりしょ",
  "alt_readings": [],
  "meaning_ko": "견적서",
  "level": 2,
  "reading_type": "mixed",
  "category": "transaction",
  "jlpt": "none",
  "priority": 1,
  "bjt_priority": 5,
  "example": "見積書をご確認ください。"
}
```

| 필드 | 값 |
| --- | --- |
| `id` | 전체 파일에서 고유한 값 |
| `reading` | 히라가나만 사용. 문장(level 3·4)은 반각 공백과 `ー` 허용 |
| `level` | 1 단어 · 2 복합어 · 3 짧은 문장 · 4 비즈니스 문장 |
| `reading_type` | `onyomi` · `kunyomi` · `mixed` · `jukujikun` |
| `category` | `transaction` `contract` `finance` `hr` `meeting` `report` `schedule` `operation` `customer` `general` |
| `priority` | 1~4 (신규 문항이 나오는 순서) |
| `grammar` | (선택) 문장에 포함된 N1 문법 |

같은 표기가 여러 파일에 있으면 priority가 높은(숫자가 작은) 쪽만 사용합니다.
문항별 학습 기록은 `id`로 저장되므로, 이미 학습한 문항의 `id`는 바꾸지 마세요.

## 구조

```
src/
  lib/
    kana.ts     가나 정규화, 로마자 변환
    grade.ts    정답 판정, 오답 유형 분류
    srs.ts      복습 간격 (Spaced Repetition)
    queue.ts    무한 모드 출제 순서
    stats.ts    KPI 계산
    storage.ts  localStorage 저장, 백업
    data.ts     콘텐츠 로딩, 한자별 관련 단어
  components/   Drill · StatsPage · WordList · SettingsPage
  data/         콘텐츠 JSON
scripts/validate-data.mjs
```

## 이후 확장 후보 (MVP 제외)

BJT 청해·청독해·독해 문제, 음성 문제, 비즈니스 경어 전환 문제, N1 문법 문제, AI 문제 자동 생성.
문항 스키마에 `level`과 `grammar`가 있으므로, 새 문제 유형을 추가할 때 같은 저장 구조를 그대로 쓸 수 있습니다.
